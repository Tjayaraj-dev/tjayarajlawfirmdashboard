01 — Orientation

What this system is

The Command Centre replaces paper files and scattered spreadsheets with one secure, cloud-based home for the firm's clients, cases, court dates and documents. It runs in any web browser — desktop or mobile — and every member of the firm has their own login.

It is built around a single, simple idea that mirrors how the firm already works:

CLIENT  ──▶  MATTER (the case file)  ──┬──▶  EVENTS   (the 5 attendance forms)
                                    └──▶  DOCUMENTS (pleadings, affidavits …)

         CALENDAR   ◀── draws every hearing & next date from Matters + Events
         DASHBOARD  ◀── summarises the whole firm at a glance
         AUDIT LOG  ◀── records every action and every file viewed

A client can have many cases over time. Each case carries its events (what happened in court, prison visits, interviews) and its documents. Every other screen is either a way into that chain, or a view that reads from it.

Two kinds of user

RoleSeesCan do
Admin (e.g. Mr Jayaraj)Everything, including admin screens & the audit logFull control — manage users, configure the firm, permanently delete, freeze the system
Staff (lawyers / clerks)The day-to-day workspace onlyCreate & edit clients, cases, events, documents; archive (not permanently delete)

Access isn't just hidden on screen — the database itself enforces who can see what. Even outside the app, the data stays locked to the right person.

02 — The screens, A to Z

Everyday workspace

Overview (Dashboard) Home

The landing screen after sign-in. Shows live counts — active cases, hearings in the next fortnight, total clients, total documents — plus a list of upcoming hearings and a running activity feed. It stores nothing itself; it reads from everything below, so it's always current.

Clients Who the firm acts for

Individuals and companies. The intake form captures an auto-assigned Client ID (e.g. TJC-C-0007), an old-file reference number, type, NRIC / company no., and separate phone, email and address. A single client can hold many cases. You can even open the client's first case directly from the intake form.

Matters The case ledger — the heart

Every case file the firm holds. Each matter belongs to one client and records the court, accused, charges, prosecutor / DPP, status and next hearing. A unique file reference (TJC ref) identifies it. Clicking a matter opens its detail page.

Inside a Matter Events + Documents live here

The case file's detail page holds two things:

· Events timeline — the five firm forms, logged as the case progresses: Court Attendance, Zoom Session, Prison Attendance, Client Interview, Minutes of Proceedings. Each event can carry a next date.

· Documents — files filed against this case, with automatic version history (re-uploading a file keeps the old copy).

Documents (vault) Firm-wide

Every document across every case in one searchable list — pleadings, affidavits, KYC, evidence. Files always belong to a matter; this is the bird's-eye view. You can also upload here by picking the matter first.

Calendar The diary

A month view that automatically shows every hearing and every event's "next date" across the firm — colour-coded by type. You don't type into it directly; it draws from the matters and events. Log a court date on a case and it appears here instantly. Each entry links straight back to its matter.

02 — The screens, A to Z (cont.)

Administration & oversight

Visible to admins only. Staff never see these.

Users

Every lawyer and clerk with their own login and role. Admins promote or demote between Admin and Staff here. Per-person logins are what make the audit trail meaningful.

Case Types

The firm's editable list of practice areas (Criminal Defence, Civil Litigation, Conveyancing …) used to categorise matters. Add, rename or remove to match the firm's taxonomy.

Document Categories

The filing labels for the vault — seeded with six defaults: Pleadings, Affidavits, Correspondence, KYC, Evidence, Invoices. Fully editable.

Audit Log

An append-only record of every action — who created, edited, archived, deleted or viewed/downloaded a record, and when. This is the Bar Council answer to "who saw this file." It cannot be altered or erased.

Settings

Firm profile (name, Bar Council no., retention years, sender email, brand colour), each user's two-factor authentication, and the Emergency Read-Only switch.

03 — How a real case flows

From walk-in to hearing

  1. A client walks in. Create the Client via the intake form. If they're bringing a case, open their first Matter in the same step.
  2. The Matter becomes the case file — court, accused, charges, prosecutor/DPP, status, file reference.
  3. As the case runs, counsel logs Events on the matter — a court attendance, a prison visit, a client interview. Each event can set the next date.
  4. Documents are uploaded to the matter — affidavits, pleadings — each new version kept.
  5. The Calendar updates automatically. Every next date and hearing now shows in the month diary, colour-coded, linked back to the case.
  6. The Dashboard summarises the whole firm — what's active, what's coming, who did what.
  7. Everything is recorded in the Audit Log — silently, permanently.

Why "next date" matters

When counsel logs a court, Zoom or proceedings event and fills in the next date, the system also updates the case's headline "next hearing" — so the matters list, the calendar and the dashboard all stay in step without anyone re-typing it. One entry, everywhere it needs to be.

04 — The protection layer

Security & compliance

Much of the system's value is invisible — it sits underneath every screen, protecting the firm's most sensitive asset: its client data.

Per-person logins

No shared passwords. Every action is attributable to a named person — which is what makes the audit log, and PI-insurance, meaningful.

Two-factor authentication

Admin accounts require a 6-digit code from an authenticator app, not just a password.

Database-enforced access

Row-Level Security: the database itself decides who sees what. Even if the app were bypassed, the data stays locked.

Full audit trail

Every view, edit, download and deletion is recorded, append-only. The Bar Council "who saw this file" answer.

Signed-link documents

Files are never public. Download links are generated on demand and expire within 60 seconds.

Soft-delete by default

Records are archived, not destroyed — protecting against accidental and malicious loss.

Emergency Read-Only Mode

One switch freezes all changes firm-wide during a dispute or incident, while keeping everything viewable.

Singapore region & backups

Data hosted in-region with daily backups, point-in-time recovery and an independent off-site copy (triple-redundant).
